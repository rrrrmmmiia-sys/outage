# ربات تلگرامی هشدار قطعی برق مازندران

## معماری

این ربات فقط برای استان مازندران فعاله و هیچ تماسی با هیچ AI ای نداره.
داده‌ی قطعی‌ها توسط **GitHub Actions** هر شب حدود ۰۰:۳۰ بامداد به وقت ایران
از سایت [baboliha.ir](https://baboliha.ir/) خونده میشه و مستقیم تو دیتابیس
Postgres ربات نوشته میشه (اسکریپت `fetch_outages_postgres.py`).
ربات فقط از دیتابیس می‌خونه و هشدار می‌فرسته.

```
outage-bot/
├── main.py                  # نقطه‌ی ورود اجرای ربات + ثبت منوی دستورات
├── config.py                 # خواندن متغیرهای محیطی
├── fetch_outages_postgres.py # جاب شبانه (GitHub Actions): دریافت و درج قطعی‌ها
├── requirements.txt
├── Procfile                  # برای ریلوی
├── .github/workflows/
│   └── fetch-outages.yml     # کرون شبانه‌ی گیت‌هاب اکشن
├── bot/
│   ├── handlers.py           # منطق مکالمه‌ی تلگرام + دستورات / و داشبورد
│   └── keyboards.py          # کیبوردهای اینلاین (فقط شهرستان‌های مازندران)
├── db/
│   ├── models.py              # مدل‌های SQLAlchemy
│   └── database.py            # اتصال + مهاجرت‌های idempotent
├── services/
│   ├── outage_service.py      # ساخت region_key، خواندن کش، جست‌وجوی مشابه
│   └── scheduler.py           # هشدارها (هر ۱ دقیقه) + خلاصه‌ی شبانه
└── data/
    └── iran_divisions.py       # شهرستان‌های استان مازندران
```

## قابلیت‌ها

- ثبت تا ۳ مکان (شهرستان + کلمه‌ی کلیدی منطقه) برای هر کاربر
- **دو هشدار** برای هر قطعی: حدود ۱ ساعت قبل و ۱۰ دقیقه قبل
- پشتیبانی از **چند قطعی در روز** برای یک منطقه (صبح و عصر و…)
- خلاصه‌ی شبانه ساعت ۲۲:۱۵: ساعت قطعی فردای همه‌ی مکان‌ها در یک پیام
- داشبورد `/status`: وضعیت همه‌ی مکان‌های کاربر در یک پیام
- منوی دستورات تلگرام (`/`) کنار دکمه‌ی سنجاق: start، status، add، locations، help
- صفحه‌بندی لیست «مکان‌های من»

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | از [@BotFather](https://t.me/BotFather) |
| `DATABASE_URL` | — | Postgres (ریلوی خودش می‌سازه) |
| `TIMEZONE` | `Asia/Tehran` | منطقه‌ی زمانی محاسبات |
| `MAX_LOCATIONS_PER_USER` | `3` | حداکثر مکان برای هر کاربر |
| `NOTIFY_MINUTES_BEFORE` | `10` | هشدار ده دقیقه قبل |
| `NOTIFY_HOUR_BEFORE_MINUTES` | `60` | هشدار دوم؛ `0` یعنی خاموش |
| `NIGHTLY_SUMMARY_HOUR` | `22` | ساعت خلاصه‌ی شبانه |
| `NIGHTLY_SUMMARY_MINUTE` | `15` | دقیقه‌ی خلاصه‌ی شبانه |

## راه‌اندازی محلی

```bash
python -m venv venv
source venv/bin/activate        # لینوکس/مک — ویندوز: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # و پر کردن مقادیر
python main.py
```

با اولین اجرا، جدول‌های دیتابیس و مهاجرت‌ها خودکار اعمال میشن.

## دیپلوی روی ریلوی

1. پروژه رو به ریپازیتوری گیت‌هاب وصل کن (یا `railway up`).
2. پلاگین **PostgreSQL** رو اضافه کن تا `DATABASE_URL` ساخته بشه.
3. متغیرهای جدول بالا (به‌جز DATABASE_URL) رو دستی ست کن.
4. نوع سرویس **Worker** باشه (ریلوی از `Procfile` تشخیص میده).

## جاب شبانه‌ی گیت‌هاب اکشن

`.github/workflows/fetch-outages.yml` هر شب ۲۱:۰۰ UTC (۰۰:۳۰ تهران)
اجرا میشه. فقط یک secret لازم داره:

- `DATABASE_URL` = مقدار `DATABASE_PUBLIC_URL` سرویس Postgres ریلوی
  (چون اکشن از بیرون شبکه‌ی ریلوی وصل میشه).

⚠️ اسکریپت تاریخ رو با `Asia/Tehran` حساب می‌کنه نه ساعت سرور — چون
runner های گیت‌هاب UTC هستن و اجرای بعد از نیمه‌شب ایران با تاریخِ
UTC باعث میشد هیچ کارتی برای «امروز» پیدا نشه.

## نکات شناخته‌شده

- داده‌ی `outage_cache` کاملاً به جاب شبانه‌ی گیت‌هاب بستگی داره؛ اگه
  یک شب اجرا نشه یا سایت تغییر کنه، اون روز هشداری نمیره. تب Actions رو
  چک کن یا یه مانیتورینگ ساده برای «ردیف امروز هست؟» بذار.
- تطبیق کاربر به قطعی دو مرحله‌ایه: اول دقیق روی `region_key`، بعد
  فالبکِ «district داخل note». اگه آدرس خیلی کلی ثبت کنی ممکنه چند
  قطعی هم‌شهرستان تطبیق بخورن.
