# ربات تلگرامی هشدار قطعی برق

## ساختار پروژه

⚠️ **تغییر معماری**: این ربات الان فقط برای استان مازندران فعاله، و
دیگه هیچ تماسی با هیچ AI (جمنای یا هر چیز دیگه) نداره. جست‌وجوی ساعت
قطعی برعهده‌ی یک **Hermes Agent** جداست که هر شب ساعت ۲۲:۰۰ مستقیم تو
دیتابیس می‌نویسه. جزئیات کامل این اتصال تو `HERMES_INTEGRATION.md` هست.

```
outage-bot/
├── main.py                  # نقطه‌ی ورود اجرای ربات
├── config.py                 # خواندن متغیرهای محیطی
├── requirements.txt
├── Procfile                  # برای ریلوی
├── HERMES_INTEGRATION.md      # راهنمای اتصال جاب شبانه‌ی هرمس به دیتابیس
├── bot/
│   ├── handlers.py           # منطق مکالمه‌ی تلگرام (افزودن/حذف/لیست مکان)
│   └── keyboards.py          # کیبوردهای اینلاین (فقط شهرستان‌های مازندران)
├── db/
│   ├── models.py              # مدل‌های SQLAlchemy
│   └── database.py            # اتصال به دیتابیس
├── services/
│   ├── outage_service.py      # ساخت region_key، خواندن کش، و پیدا کردن مکان‌های مشابه (fuzzy search)
│   └── scheduler.py           # فقط واحد هشدار (هر ۱ دقیقه)
└── data/
    └── iran_divisions.py       # فقط استان مازندران (نیاز به تایید نهایی داره)
```

## راه‌اندازی محلی (تست قبل از دیپلوی)

1. پایتون ۳.۱۱ یا بالاتر نصب باشه.
2. محیط مجازی بساز و پکیج‌ها رو نصب کن:
   ```
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```
3. فایل `.env.example` رو کپی کن به `.env` و مقادیر واقعی رو پر کن:
   - `TELEGRAM_BOT_TOKEN`: از [@BotFather](https://t.me/BotFather) بگیر.
   - `DATABASE_URL`: یک دیتابیس PostgreSQL محلی یا از ریلوی.
4. اجرا کن:
   ```
   python main.py
   ```
   با اجرای اولیه، جدول‌های دیتابیس خودکار ساخته میشن.

## دیپلوی روی ریلوی

1. یک پروژه‌ی جدید در Railway بساز و ریپازیتوری گیت‌هاب این پوشه رو بهش وصل کن
   (یا از دستور `railway up` با CLI ریلوی استفاده کن).
2. از داشبورد ریلوی، پلاگین **PostgreSQL** رو به پروژه اضافه کن. ریلوی خودش
   متغیر `DATABASE_URL` رو می‌سازه و به سرویس ربات تزریق می‌کنه.
3. تو تنظیمات سرویس ربات (Variables)، این‌ها رو دستی اضافه کن:
   - `TELEGRAM_BOT_TOKEN`
   - `TIMEZONE=Asia/Tehran`
   - `MAX_LOCATIONS_PER_USER=3`
   - `NOTIFY_MINUTES_BEFORE=10`
4. مطمئن شو نوع سرویس **Worker** باشه نه Web (چون این ربات با polling کار
   می‌کنه و نیازی به باز کردن پورت HTTP نداره). ریلوی از روی `Procfile`
   (خط `worker: python main.py`) این رو تشخیص میده.
5. دیپلوی کن. لاگ‌ها رو چک کن تا مطمئن بشی پیام «ربات در حال اجراست» دیده میشه.

## نکات مهم امنیتی
- کلیدهای API رو هیچ‌وقت داخل کد commit نکن؛ فقط از طریق Variables ریلوی ست کن.
- اگه کلیدی رو تصادفی جایی (چت، گیت‌هاب، اسکرین‌شات) به اشتراک گذاشتی،
  فوراً از Google AI Studio باطلش کن و کلید جدید بساز.

## نکات مربوط به داده‌ی تقسیمات کشوری
فایل `data/iran_divisions.py` به‌صورت دستی تهیه شده و ممکنه همه‌ی
شهرستان‌های جدید یا تغییرات اخیر رو نداشته باشه. قبل از استفاده‌ی
گسترده، پیشنهاد میشه این لیست رو با یک منبع رسمی (مثل سایت مرکز آمار
ایران) تطبیق بدی.

## محدودیت‌های شناخته‌شده / نکات توسعه‌ی بعدی
- هشدار ۱۰ دقیقه‌ای بر اساس یک بازه‌ی ۲ دقیقه‌ای چک میشه (هر دقیقه اجرا
  میشه)؛ در موارد نادر نزدیک نیمه‌شب ممکنه دقیق نباشه.
- اگه برای یک منطقه `found = false` تو `outage_cache` ثبت بشه (یعنی
  هرمس چیزی پیدا نکرده)، فعلاً به کاربر پیامی فرستاده نمیشه؛ می‌تونی
  این رو گسترش بدی تا مثلاً یک پیام «اطلاعاتی پیدا نشد» هم به کاربر بره.
- درستیِ داده‌ی `outage_cache` کاملاً به کیفیت جاب شبانه‌ی هرمس بستگی
  داره؛ اگه هرمس یک شب اجرا نشه یا خطا بده، اون روز هیچ هشداری فرستاده
  نمیشه. پیشنهاد میشه یه مانیتورینگ ساده (مثلاً چک کردن اینکه هر روز
  ردیف جدید تو `outage_cache` برای امروز هست یا نه) رو هم اضافه کنی.
- تشخیص مکان‌های مشابه (`find_similar_locations`) الان فقط داخل همون
  شهرستان جست‌وجو می‌کنه و با آستانه‌ی شباهت ثابت (`0.25`) کار می‌کنه؛
  اگه دیدی خیلی مکان نامرتبط پیشنهاد میشه یا برعکس مکان‌های واقعاً
  مشابه رو نشون نمیده، این آستانه رو تو `services/outage_service.py`
  تنظیم کن.
